# 花花和松松

> 一盆重瓣黄的长寿花，一盆小叶罗汉松，住在杭州一间朝北的走廊里。

一个替它们看天、算水、记花事的本机小站。手绘插画由另一条会话生成，前端做了尺寸适配。

一个跑在自己 Mac 上的小型养护看板。手机连同一个 WiFi 就能打开，两端的记录实时同步。
不是通用园艺 App，是专门按**你这几盆花**的真实参数（盆径、根球占比、排水、阳台几何）算出来的。

```
电脑：http://127.0.0.1:7788
手机：http://<这台 Mac 的局域网 IP>:7788
```

---

## 一、怎么启动

```bash
cd ~/Code/花花和松松
node server.js
```

或者双击 `start.command`（会自动打开终端并启动）。
关掉终端窗口服务就停；想让它常驻，可以 `nohup node server.js > /tmp/plant.log 2>&1 &`。

启动后终端会打印两个地址，手机用**局域网那个**（需要同一个 WiFi，且 macOS 防火墙放行 node）。

## 二、它到底在算什么

### 1）怎么浇：浇到底孔出水

**浇水不再数毫升。** 有孔的盆一律浇到底孔出水——出水说明基质已经回到持水量，
再倒只是从底孔流走；顺带把攒下的盐冲掉，下层根也喝得到。
（无孔盆物理上浇不到出水，只能套盆或按比例分次给。）

毫升数留在模型里，用来回答另一个问题：**这一盆能留住多少水**。

```
盆内容积 V   = π·h/12 · (D² + Dd + d²)        // 圆台，D 盆口、d 盆底、h 盆高
能存给根用的水 = V × 土面填装 × 基质有效水率 × 65% × 根球占盆比
```

| 植物 | 盆 | V | 浇透后能存 | 日耗(走廊) | 一次浇透能撑 |
|---|---|---|---|---|---|
| 长寿花 | 13×10×12 | 1646 ml | **450 ml** | ≈ 30–40 ml | ≈ 12–15 天 |
| 罗汉松 | 9×7×9.5 | 477 ml | **100 ml** | ≈ 16 ml | ≈ 6–7 天 |

65% 是留的缓冲：只用掉六成多的有效水就浇，不逼到永久萎蔫点。
基质有效水率取自 Rutgers Cooperative Extension FS812 的实测表（椰糠/泥炭 0.48、腐叶土 0.44、颗粒土 0.30）。

### 几点浇：按当天的气象算，不写死

每天给一个 HH:MM，依据都是能查的园艺/生理口径：

| 条件 | 怎么进模型 | 出处 |
|---|---|---|
| **热天 → 傍晚** | 白天最高 ≥28℃：`16:00–日落前` 里挑，越晚越凉；中午蒸发最凶、冷水激热土 | 热天避开蒸发高峰；CAM 植物夜间气孔才开 |
| **冷天 → 上午** | 最高 <14℃：`09:00–11:30` 里挑最暖的一段，浇完留大半天排水回温 | 夜里又冷又湿 → 烂根 |
| 温和天 → 早上 | 5–9 点浇完，叶面/土表当天能干 | Iowa State Univ. Extension |
| 凉爽时段盆面蒸发少 | 逐小时辐射进打分（700 W/m² 当"很晒"） | RHS《How to water containers》 |
| 根区温度 | 土温=过去 24 h 气温的指数滑动平均（τ=8 h）；冷天把浇水挪到一天里最暖的一段 | 根在 10–12℃ 以下吸水速率明显下降 |
| 别湿着过夜 | 候选时段必须离日落 ≥2.5 h | — |
| 露天＋马上要下雨 | 后 3 小时降水越多扣分越多（白浇） | — |
| 外出台当天 | 搬出去 1 小时内不浇（土没回暖、盆还滴水） | — |
| 人不在 | 只在 `site.waterWindow`（默认 08:00–19:00）里挑 | — |

想固定钟点：植物详情里把「浇水钟点」改成固定时刻即可（`schedule.waterMode='fixed'`）。

### 场地系数

`dailyUse = 基准 × ET₀/1.3 × 校准 × 场地系数`（阳台 1.0 / 走廊 0.65 / 室内 0.5）。
走廊没风、没直射、湿度高，蒸发明显慢。降雨补偿只在"阳台 + 露天"时计入。

### 2）多久浇一次

```
日耗 = 基准日耗 × (今天 ET₀ / 1.3) × 校准系数
```

`ET₀` 直接来自天气预报（FAO 参考蒸散量），所以晴天浇得勤、阴雨天自动拉长。
日耗里的蒸腾项跟当天的今日总光量走（走廊 + 西阳台按实际搬动时间拼），
没写 `traits.kTrans` 的植株默认按「在它需要的光下正好 targetWetDays 干完」反解，
免得小盆套用大盆系数、一晒太阳就两天浇一次。
下雨且盆在露天时，按盆口面积把雨水折算成补水（打 6 折，叶冠会截留）。

**校准**：跳过一次浇水任务，选"还湿"→ 系数 ×0.88；选"已经干透了"→ ×1.12。
每株单独记录，越快用越准。

### 3）晒到多少太阳

用太阳方位角/高度角 + 栏板高度 + 盆位进深算遮挡，斜射时用 `cos(斜角)` 修正阴影投影。
输出「盆位直射小时数」和 DLI（mol/m²/d），并直接反解**要垫多高才够 3 小时**。

这一项对输入极其敏感：**朝向设错，结果全错**。
朝南 180° 配 110 cm 栏板 + 70 cm 进深，11 月盆放地上只有 0 小时，垫到 50 cm 才有 3 小时。
**朝北（0°）则整个 11 月零直射**，垫多高都没用。

放在走廊/室内时不算直射，只算散射：`DLI = 室外 DLI × 走廊透光率`（默认 37%，可调）。
测法：手机测光 App 同时量门口和阳台的照度，比值就是透光率。

**今日总光量按"人在哪儿 × 那段时间的光"算**：每次搬完点一下「搬到西阳台 / 搬回走廊」
（勾当天的搬动任务也算一次），搬去的那一段按露天光（≈1.0，不再折透射率），其余时间按走廊透光率，
逐小时积分成当天的 DLI。比如 11/13 实际 12:58–17:38 在西阳台 = 走廊 1.3 + 西阳台 5.0 = 6.3
（全天不动走廊是 1.9）。没点过的日期才回落到计划窗口（13:00–17:00）；早上就搬过去，
光量就从早上开始算。天气页「未来 9 天」的表格按单个地点对比，下面的「今日总光量」曲线才是合计。

外出台窗口内下雨（单小时 ≥1.2 mm 或累计 ≥2.5 mm）、白天低于 8℃，或太阳方位不在栏杆开口内，
当天就不算搬出去。外出台的生效日期取 `site.measured.at`，之前的日期不追溯，免得把历史浇水量算歪。

### 4）周末放哪儿

周末人不来，所以**不做"放哪儿更好"的比较**：两盆现在停在哪（走廊 / 西阳台），就在那儿待两天，
一条搬动任务都不生成。

唯一会动的是**温度**：按它们现在待的地方折算夜间温度——阳台就是露天那档（`BALCONY_WARM_C=0`），
走廊是半室内（`+5℃`）——低于 `roomLine()`（耐受线再下 5℃，也就是接近冰点时，设置页可调）才在**周五下班搬进房间、周一搬回**。天气预报突然变冷（急降温）走的是同一条规则：温度一变，第二天就会提示。

工作日不变：走廊为主，有直射窗口的下午搬到西阳台晒太阳，傍晚搬回走廊；走廊夜里真到冰点附近才搬进实验室。
已经在外面待着的日子（比如西阳台过周末）只生成傍晚"搬回来"那一次，早上不再让你搬一趟。

### 5）待办与历史

任务列表只算「今天 + 未来 7 天」，但**做过没做过都会被记下来**，不会因为翻篇就消失。

- 每次加载（打开、切回标签页、每分钟的静默刷新）把当前算出来的任务拍进 `state.taskHistory`：
  `{ 'YYYY-MM-DD': { 任务id: {kind,title,time,plantId} } }`，只留最近 120 天。
  完成与否不写第二份，仍然只认 `tasksDone`——一个真相源。
- 右侧小日历：**只有已经过去、并且有没做完的日子才标红点**（未来的日子还没发生，不标）。
  左右可以翻月；点任意一天弹出那天的清单（时间、标题、完成/跳过/没做）。
  **清单里可以补勾**：那天其实做了、只是忘了点，点右边圆圈补上，红点就消了；补勾浇水会把基准记到那一天。
- 「以前没做完的」卡片：把过期还没勾的挑出来列着，点日期直接看那天。
- 老数据只有 `tasksDone`（任务 id 里带日期），第一次加载会回填成历史条目。这些日子标成
  「只有完成记录」——只代表勾过的，缺的不等于没做，所以**不标红点、不算欠账**。
- **已经在外面就不搬第二趟**：外出台还开着（`currentMovePlace` 是 `trip`）的那天，早上不生成"搬出去"，
  只生成傍晚"搬回来"；西阳台过周末的周一同样只搬傍晚那一次。
- **夜里温度两处修正**：日最低/最高温取 ECMWF / GFS / ICON 三家**中位数**（单模型在这片常比中央气象台低 4℃）；
  阳台有顶棚、贴着楼体，夜里按 **+2℃** 折算（走廊则是 +5℃、再留 3℃ 宽容）。
- **休息日（周六周日）不生成要到场的任务**：巡霉、拍照、施肥、搬动、外出台都跳过；浇水这类有截止日的
  会提前到周五（"本来周日到期，改到周五"），过期了顺延到周一。
- 历史是只读的。补勾过去的事请回那天去看；在这里补勾会把 `lastWateredAt` 记成当前时间，把浇水模型算歪。

## 三、必须填对的三个参数

设置页 → 阳台几何 / 植株参数：

1. **阳台朝向**（手机指南针贴栏板朝外测）
2. **盆口内径**（尺子量，直接决定 ml）
3. **是否有排水孔**（决定能不能浇透）

这三项没填对，数字就是错的。其余都有合理默认值。

## 四、拍照与 AI 诊断

照片存在 `data/photos/`，浏览器上传前会压到 1500 px JPEG。
点「让模型看看」时，服务端把照片 + 当时的养护数据（几天没浇、剩余水分、7 天温湿度/ET₀/日照）
一起发给视觉模型，要求按固定 JSON 返回健康分、征象、处置建议。

**Key 只存在这台 Mac 的 `data/config.json`，不会下发到浏览器。**

**当前配置的是本机 magpie 网关**（和这个对话同一个模型、同样 `reasoning_effort: max`）：

| 项 | 值 |
|---|---|
| Base URL | `http://127.0.0.1:3425/v1` |
| 模型 | `commandcode-plan/deepseek/deepseek-v4.1-flash` |
| 口令 | `magpie`（本地网关的固定口令） |
| 思考强度 | `max`，max_tokens 4000 |

⚠️ 这个网关只在 **magpie / DSH 运行时**存在。DSH 关掉后照片分析会报"连不上网关"，
但浇水、光照、任务这些计算全在本地，照常工作。

⚠️ `max` 档的思考会吃满输出额度：实测一次约 1.6k 思考 token + 0.2k 输出。
`max_tokens` 给 1000 会返回空内容，所以设成 4000。一次约 20 秒。

设置页也有其它服务商预设：

| 服务商 | Base URL | 常用模型 |
|---|---|---|
| 本机 magpie | `http://127.0.0.1:3425/v1` | `commandcode-plan/deepseek/deepseek-v4.1-flash` |
| 通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k-vision-preview` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

只要是 OpenAI 兼容的 `/chat/completions` + 支持 `image_url` 的模型都能接。

## 五、提醒的边界（说清楚）

- 浏览器通知只在**页面开着**时弹。手机走 `http://局域网IP` 属于非安全上下文，
  iOS/Chrome 不会给通知权限——所以真正靠得住的是：**每天早上打开看板** + **导出的 .ics**。
- `.ics` 里有 14 天任务和提前 10 分钟的闹钟，导进手机日历就是系统级提醒。
- 逾期的任务不会消失，会标红一直留着。

## 八、写保护（可选）

## 九、常见问题

**手机打不开？**
1. 确认同一个 WiFi（宿舍/教研室的路由器，不是访客网络）；
2. 校园网常常开启**客户端隔离**，手机和 Mac 互相 ping 不通——这种情况用手机热点给 Mac 连，或换个路由器；
3. macOS 首次运行会弹"是否允许 node 接受传入连接"，要允许。

**数字看起来不对？**
先检查这三项：阳台朝向、盆口内径、有没有排水孔。改完立刻重算。
另外 `11 月 12 日 ET₀=1.32`，一盆 13 cm 的长寿花日耗约 41 ml，可存 350 ml，所以 9 天才浇——这是秋天该有的节奏，
不是模型偷懒。到了 6 月 ET₀ 会到 4–5，同一盆就变成 2–3 天一次。

**照片会占空间吗？**
上传前压到 1500 px JPEG，一张 200–400 KB，一年 100 张也就 40 MB。

**能不能换城市？**
设置页改经纬度即可，天气和日照会跟着变。

## 九、让别人也能打开（公网访问）

本机跑的服务，别人打不开是正常的——你家/学校网络没有公网 IP。三种做法：

### A. 临时公网隧道（已配好，双击就能用）

```bash
./share.command
```

它会依次启动服务、建 Cloudflare 隧道，然后打印两个链接：

- `https://xxx.trycloudflare.com/?t=<口令>` —— **自己用**，能改数据
- `https://xxx.trycloudflare.com` —— **发给别人**，只读

特点：Mac 必须开着；关闭后地址失效，重开会拿到**新地址**；免费、无需注册。

### B. 固定地址（推荐长期用）

1. 有域名的话，`cloudflared tunnel login` → `cloudflared tunnel create plant`
   → `cloudflared tunnel route dns plant plant.你的域名.com`
   → 用 `config.yml` 跑命名隧道，地址就固定了。
2. 或者买台最便宜的云服务器（轻量 24 元/月），把整个目录扔上去跑 `node server.js`，
   前面挂 Caddy 做 HTTPS。国内服务器走 IP:端口不需要备案，用域名 80/443 要备案。

### C. 纯静态只读（不需要 Mac 开机）

把当前状态导成一个静态站点丢到 Netlify / GitHub Pages，只能看不能改。
适合“就想给大家看看我的花”，不适合打卡。

### 写保护是怎么做的

`server.js` 里有个 `TOKEN`（从 `.token` 文件读）。设了以后：
- `GET` 全部放行——谁都能看；
- 写操作（改状态、上传照片、调模型）必须带 `x-plant-token` 头或 `?t=` 参数，否则 401。

浏览器第一次用 `?t=口令` 打开会把口令存在 localStorage，并自动把地址栏里的 `?t=` 抹掉，
免得你截图分享时把口令漏出去。别人打开就是干净的只读页面。

改口令：编辑 `.token`（随便一串），重启服务即可。

## 十、Tailscale 私网访问（可选）

想在外网也能打开、又不想把端口暴露到公网，可以用 Tailscale：

1. Mac 和手机各装 Tailscale，登同一个账号；
2. Mac 上 `tailscale serve --bg 7788`（或直接让手机连同一个 tailnet）；
3. 用 `tailscale status` 查到的地址打开，形如 `http://<主机名>.<你的 tailnet>.ts.net:7788`。

手机连上 tailnet 后，任何网络下都能直接打开，不需要公网 IP、不需要域名、不需要 Cloudflare 隧道。

**登录自启**：`~/Library/LaunchAgents/com.shentianshuo.plantcare.plist` 已写好，
下次登录会自动 `node server.js`。想立刻启用：

```bash
# 先停掉手动跑的那个，再加载
pkill -f "node server.js"
launchctl load -w ~/Library/LaunchAgents/com.shentianshuo.plantcare.plist
```

**出口节点**（让手机流量走 Mac）：

```bash
sudo /Applications/Tailscale.app/Contents/MacOS/Tailscale up --advertise-exit-node --accept-dns=true
```

然后去 https://login.tailscale.com/admin/machines → 这台机器 → ⋯ → Edit route settings
→ 勾选 **Use as exit node**；手机 Tailscale App 里选它为 Exit node。

## 十一、Sites 云端站点

线上版不是静态截图：`worker/index.js` 在 Sites 上提供与本地一致的 `/api`，状态、配置、
天气缓存和照片都存在站点的 D1 数据库里。本地 `server.js` 不受影响，仍然可以继续用。

站点地址：部署后会得到一个站点域名（默认仅本人可访问），换成你自己的即可。

```bash
npm run build:sites       # 生成 Sites 需要的 dist/
npm run package:sites     # 如需手动检查发布包，会在根目录生成 site.tar.gz
```

- `.openai/hosting.json` 只放 `project_id`、逻辑 D1/R2 绑定，不放密钥。
- 本地 `data/` 不会进入发布包；站点首次上线可通过 Sites 环境变量
  `SEED_STATE_JSON` 导入一份初始状态，之后由 D1 自己保存。
- 站点若设置了 `PLANT_TOKEN`，读取照常，改状态、上传照片和修改模型配置需要口令。
- 改完 `public/` 或 `worker/` 后重新构建并发布同一个 Sites 项目即可，站点数据不会被覆盖。
